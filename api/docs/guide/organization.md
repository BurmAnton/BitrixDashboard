## Введение

Добро пожаловать в документацию REST API для работы с организациями. Этот API предоставляет возможность получения информации об организациях, их типах, регионах, сферах деятельности и связанных проектах.

**Особенности API:** поддерживает расширенную фильтрацию по различным параметрам, включая вложенные связи (регионы, федеральные округа, проекты).

## 1. Аутентификация

Для доступа к API требуется токен.

1. В админ-панели Django перейдите в раздел «Токены».
2. Создайте новый токен для нужного пользователя.
3. Сохраните токен для будущего использования.

## 2. Основной эндпоинт

### 2.1 Получение данных об организациях

| | |
|---|---|
| **Эндпоинт** | `/api/organization/` |
| **Метод HTTP** | GET |
| **Аутентификация** | Требуется (токен в заголовке Authorization) |
| **Пагинация** | Поддерживается (стандартная Django REST) |

### 2.2 Формат запроса

**Заголовки обязательные:**

| Заголовок | Значение | Описание |
|-----------|----------|----------|
| `Authorization` | `Token YOUR_TOKEN` | Токен аутентификации |
| `Accept` | `application/json` | Формат ответа (рекомендуется) |

### 2.3 Примеры использования

**Пример 1: JavaScript (Fetch API)**

```javascript
// Получение всех организаций
fetch('https://bitrix24.tuna-edu.ru/api/organization/', {
    method: 'GET',
    headers: {
        'Authorization': 'Token 4a8389aa7f015d3a68e44e3f4bae94d63c7ac097',
        'Accept': 'application/json'
    }
})
.then(response => response.json())
.then(data => console.log(data))
.catch(error => console.error('Ошибка:', error));
```

**Пример 2: cURL**

```bash
curl -X GET 'https://bitrix24.tuna-edu.ru/api/organization/' \
  -H 'Authorization: Token 4a8389aa7f015d3a68e44e3f4bae94d63c7ac097' \
  -H 'Accept: application/json'
```

**Пример 3: Python (Requests)**

```python
import requests
headers = {
    'Authorization': 'Token 4a8389aa7f015d3a68e44e3f4bae94d63c7ac097',
    'Accept': 'application/json'
}
response = requests.get('https://bitrix24.tuna-edu.ru/api/organization/', headers=headers)
data = response.json()
print(data)
```

## 3. Фильтрация результатов

API поддерживает расширенную фильтрацию по различным параметрам организаций.

### 3.1 Доступные фильтры

| Фильтр | Параметр | Описание | Тип поиска | Примечание |
|--------|----------|----------|------------|------------|
| Тип организации | `type` | Тип организации (РОИВ, Коммерческая и др.) | Точное совпадение, множественное | — |
| Дата создания | `date` | Поиск по части даты создания | Частичное совпадение | Формат: YYYY-MM-DD |
| Сфера деятельности | `prof_activity` | Сфера деятельности (Здоровье, Образование) | Частичное совпадение, множественное | Только для РОИВ |
| Проект | `project` | Поиск по проектам | Частичное совпадение, множественное | По названию проекта |
| Регион | `region` | Название региона | Частичное совпадение, множественное | |
| Федеральный округ | `fed_district` | Название федерального округа | Частичное совпадение, множественное | |
| Федеральная компания | `federal` | Фильтр по федеральным компаниям | Булевый | true/false |
| Активность | `is_active` | Фильтр по активности | Булевый | true/false |

### 3.2 Синтаксис фильтрации

Фильтры передаются как query-параметры в URL:

```
/api/organization/?filter1=value1&filter2=value2
```

**Множественные значения:** `?type=РОИВ&type=Коммерческая` или `?prof_activity=Здоровье,Образование`

### 3.3 Примеры фильтрации

**Пример 1: поиск РОИВ по сфере деятельности**

```
https://bitrix24.tuna-edu.ru/api/organization/?type=РОИВ&prof_activity=образование&prof_activity=здоровье
```

**Пример 2: множественная фильтрация по регионам и округам**

```
https://bitrix24.tuna-edu.ru/api/organization/?region=Москва&region=СПб&fed_district=Центральный
```

**Пример 3: комбинированный поиск проектов**

```
https://bitrix24.tuna-edu.ru/api/organization/?project=цифровизация&project=автоматизация&type=РОИВ
```

**Пример 4: запятая-разделённые значения**

```
https://bitrix24.tuna-edu.ru/api/organization/?prof_activity=образование,здоровье&region=Москва,СПб
```

**Поддержка множественной фильтрации:** передавайте параметры повторно (`?param=value1&param=value2`) или через запятую (`param=value1,value2`). Логика AND между фильтрами.

## 4. Добавление и изменение

API поддерживает создание новых организаций и изменение существующих.

| Действие | Метод | Эндпоинт | Обязательные поля |
|----------|-------|----------|-------------------|
| Добавление | `POST` | `/api/organization/add/` | `inn` |
| Изменение | `PATCH` | `/api/organization/update/` | `inn` |

**Пример создания организации:**

```json
{
  "inn": "7701234567",
  "name": "ООО Пример",
  "type": "Коммерческая",
  "region": "Москва",
  "federal_company": false,
  "projects": ["Цифровизация"],
  "prof_activity": []
}
```

**Пример изменения организации:**

```json
{
  "inn": "7701234567",
  "name": "ООО Пример (обновлено)",
  "is_active": true
}
```

## 5. Формат ответа

### 5.1 Успешный ответ (HTTP 200 OK)

API возвращает список организаций с детальной информацией.

```json
[
    {
        "name": "ООО \"Рога и копыта\"",
        "full_name": "Общество с ограниченной ответственностью \"Рога и копыта\"",
        "type": "Коммерческая",
        "region": "Московская область",
        "federal_company": false,
        "fed_district": "Центральный",
        "prof_activity": "IT-услуги",
        "projects": [
            {"name": "Цифровизация"},
            {"name": "Автоматизация"}
        ],
        "is_active": true,
        "created_at": "2023-05-15T10:30:00Z",
        "updated_at": "2024-01-20T14:45:00Z"
    },
    {
        "name": "Минобрнауки",
        "full_name": "Министерство образования и науки",
        "type": "РОИВ",
        "region": "Москва",
        "federal_company": true,
        "fed_district": "Центральный",
        "prof_activity": "Образование",
        "projects": [
            {"name": "Национальный проект \"Образование\""}
        ],
        "is_active": true,
        "created_at": "2022-01-10T09:00:00Z",
        "updated_at": "2023-11-05T16:20:00Z"
    }
]
```

### 5.2 Структура данных в ответе

| Поле | Тип | Описание |
|------|-----|----------|
| `name` | String | Краткое название организации |
| `full_name` | String | Полное официальное название |
| `type` | String | Тип организации |
| `region` | String | Регион расположения |
| `federal_company` | Boolean | Является ли федеральной компанией |
| `fed_district` | String | Федеральный округ |
| `prof_activity` | String | Сфера деятельности (для РОИВ) |
| `projects` | Array | Список проектов организации |
| `is_active` | Boolean | Активна ли организация |
| `created_at` | String (ISO 8601) | Дата создания записи |
| `updated_at` | String (ISO 8601) | Дата последнего обновления |

## 6. Коды ответов и ошибки

### 6.1 Успешные коды ответов

| Код | Описание |
|-----|----------|
| `200` | OK — запрос выполнен успешно |

### 6.2 Коды ошибок

| Код | Описание | Решение |
|-----|----------|---------|
| `400` | Bad Request — неверный формат запроса | Проверьте синтаксис URL и параметры фильтрации |
| `401` | Unauthorized — требуется аутентификация | Убедитесь, что передали корректный токен |
| `403` | Forbidden — доступ запрещён | Ваш токен не имеет прав на доступ к API |
| `404` | Not Found — ресурс не найден | Проверьте правильность URL эндпоинта |
| `500` | Internal Server Error — ошибка сервера | Попробуйте позже или обратитесь к администратору |

### 6.3 Примеры ошибок

**Ошибка 401: отсутствует токен**

```json
{
    "detail": "Authentication credentials were not provided."
}
```

**Решение:** добавьте заголовок `Authorization` с вашим токеном.
