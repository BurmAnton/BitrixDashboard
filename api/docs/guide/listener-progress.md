## Введение

Добро пожаловать в документацию REST API для отслеживания прогресса слушателей. API позволяет получать и анализировать информацию о прогрессе учащихся в программах обучения.

**Важно:** доступ требует аутентификации. Только суперпользователи проекта могут создавать и использовать токены доступа.

## 1. Аутентификация

### 1.1 Получение токена

1. В админ-панели Django перейдите в раздел «Токены».
2. Создайте новый токен для нужного пользователя.

### 1.2 Использование токена

Токен передаётся в заголовке `Authorization` каждого запроса:

```http
Authorization: Token YOUR_TOKEN_HERE
```

## 2. Основной эндпоинт

### 2.1 Получение данных о прогрессе

| | |
|---|---|
| **Эндпоинт** | `/api/listener-progress/` |
| **URL (локально)** | `http://localhost:8000/api/listener-progress/` |
| **URL (production)** | `https://bitrix24.tuna-edu.ru/api/listener-progress/` |
| **Метод HTTP** | GET |
| **Аутентификация** | Требуется (токен в заголовке Authorization) |

### 2.2 Формат запроса

| Заголовок | Значение | Описание |
|-----------|----------|----------|
| `Authorization` | `Token YOUR_TOKEN` | Токен аутентификации |
| `Content-Type` | `application/json` | Рекомендуется |

### 2.3 Примеры

**JavaScript (Fetch)**

```javascript
fetch('https://bitrix24.tuna-edu.ru/api/listener-progress/', {
  method: 'GET',
  headers: {
    'Authorization': 'Token 4a8389aa7f015d3a68e44e3f4bae94d63c7ac097',
    'Content-Type': 'application/json'
  }
})
.then(response => response.json())
.then(data => console.log(data))
.catch(error => console.error('Ошибка:', error));
```

**cURL**

```bash
curl -X GET 'https://bitrix24.tuna-edu.ru/api/listener-progress/' \
  -H 'Authorization: Token 4a8389aa7f015d3a68e44e3f4bae94d63c7ac097' \
  -H 'Content-Type: application/json'
```

**Python**

```python
import requests

headers = {
    'Authorization': 'Token 4a8389aa7f015d3a68e44e3f4bae94d63c7ac097',
    'Content-Type': 'application/json'
}

response = requests.get('https://bitrix24.tuna-edu.ru/api/listener-progress/', headers=headers)
data = response.json()
print(data)
```

## 3. Фильтрация результатов

API поддерживает фильтрацию по параметрам для поиска записей.

### 3.1 Доступные фильтры

| Фильтр | Параметр в URL | Описание | Тип поиска |
|--------|----------------|----------|------------|
| ID заявки | `application_id` | Уникальный номер заявки | Точное совпадение |
| ID заявки (содержит) | `application_id__contains` | Часть номера заявки | Частичное |
| ФИО слушателя | `full_name` | Полное имя | Точное совпадение |
| ФИО (содержит) | `full_name__contains` | Часть ФИО (без учёта регистра) | Частичное |
| Поток | `potok` | Название потока | Точное совпадение |
| Поток (содержит) | `potok__contains` | Часть названия потока | Частичное |
| Программа | `program` | Название программы | Точное совпадение |
| Программа (содержит) | `program__contains` | Часть названия программы | Частичное |

### 3.2 Синтаксис

```
/api/listener-progress/?filter1=value1&filter2=value2
```

### 3.3 Примеры фильтрации

**Точный ID заявки**

```
https://bitrix24.tuna-edu.ru/api/listener-progress/?application_id=124315555
```

**ФИО (частичное)**

```
https://bitrix24.tuna-edu.ru/api/listener-progress/?full_name__contains=ivan
```

**Поток**

```
https://bitrix24.tuna-edu.ru/api/listener-progress/?potok=11.02.2025-04.03.2025
```

**Комбинированный поиск**

```
https://bitrix24.tuna-edu.ru/api/listener-progress/?application_id=124315555&potok__contains=02.2025&program__contains=беспилотных
```

## 4. Формат ответа

### 4.1 Успешный ответ (HTTP 200 OK)

Ответ содержит пагинированный список записей о прогрессе.

```json
{
    "count": 150,
    "next": "https://bitrix24.tuna-edu.ru/api/listener-progress/?page=2",
    "previous": null,
    "results": [
        {
            "application_id": "c2a61a51-86ac-4bec-bcbc-5b87b41f6983",
            "full_name": "Иванов Иван Иванович",
            "potok": "01.01.2025-01.02.2025",
            "program": "Специалист по эксплуатации беспилотных авиационных систем...",
            "JSON_ed_progress": {
                "statistic": { },
                "attestation": "100,100,100,100,100,5"
            }
        }
    ]
}
```

(В `results` обычно до 50 объектов на страницу; структура `JSON_ed_progress` зависит от данных.)

### 4.2 Пагинация

По умолчанию возвращается до 50 записей на страницу.

| Параметр | Описание | По умолчанию | Пример |
|----------|----------|--------------|--------|
| `page` | Номер страницы | 1 | `?page=2` |
| `page_size` | Записей на страницу | 50 | `?page_size=100` |

**Примеры:**

```
GET /api/listener-progress/?page=1
GET /api/listener-progress/?page=2&page_size=20
GET /api/listener-progress/?full_name__contains=Иванов&page=1&page_size=10
```

### 4.3 Структура полей верхнего уровня

| Поле | Тип | Описание |
|------|-----|----------|
| `count` | Integer | Общее число записей по запросу (без учёта пагинации) |
| `next` | String или null | URL следующей страницы |
| `previous` | String или null | URL предыдущей страницы |
| `results` | Array | Массив объектов с данными о прогрессе |

Элементы `results` включают поля сериализатора: `application_id`, `full_name`, `potok`, `program`, `JSON_ed_progress` и др.

## 5. Коды ответов и ошибки

### 5.1 Успешные коды

| Код | Описание |
|-----|----------|
| `200` | OK — запрос выполнен успешно |

### 5.2 Коды ошибок

| Код | Описание | Решение |
|-----|----------|---------|
| `400` | Bad Request | Проверьте синтаксис URL и параметры |
| `401` | Unauthorized | Передайте корректный токен в заголовке Authorization |
| `403` | Forbidden | Нужны права; используйте учётные данные суперпользователя |
| `404` | Not Found | Проверьте URL эндпоинта |
| `500` | Internal Server Error | Попробуйте позже или обратитесь к администратору |

### 5.3 Примеры ошибок

**401 — отсутствует токен**

```json
{
  "detail": "Authentication credentials were not provided."
}
```

**Решение:** добавьте заголовок `Authorization` с токеном.

**403 — недостаточно прав**

```json
{
  "detail": "You do not have permission to perform this action."
}
```

**Решение:** используйте токен пользователя с достаточными правами (суперпользователь).

## 6. Рекомендации по использованию

### 6.1 Безопасность

- Не передавайте токены в URL — только в заголовках.
- Не публикуйте токены в исходном коде или репозиториях.
- Храните токены в переменных окружения.
- Регулярно проверяйте логи доступа к API.
- При компрометации токена создайте новый в админ-панели.

### 6.2 Оптимизация запросов

- Используйте фильтры, чтобы уменьшить объём данных.
- Для поиска по части значения используйте суффикс `__contains`.
- Комбинируйте фильтры для точности.
- При возможности кэшируйте результаты на клиенте.

### 6.3 Обработка ошибок

- Проверяйте HTTP-код ответа (200, 401, 403 и т.д.).
- Обрабатывайте сетевые исключения.
- Логируйте ошибки для отладки.
